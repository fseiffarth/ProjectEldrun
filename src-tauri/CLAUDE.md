# ProjectEldrun — Backend File Map (`src-tauri/src/`)

See the root `CLAUDE.md` for project-wide context (running, persistence, dev
workflow); see `src/CLAUDE.md` for the frontend file map.

**Top level**

| File | Purpose |
|------|---------|
| `main.rs` | Tauri app entry point, plugin registration. |
| `lib.rs` | Command registration (`generate_handler!`), app setup, hook/restore install. |
| `storage.rs` | JSON persistence helpers (read/write state files). |
| `paths.rs` | Canonical Eldrun directory paths. |
| `sysstat.rs` | Per-process CPU sampling via `/proc` (`descendant_pids`), the whole-system `SystemSnapshot` behind the monitor pane, and `machine_load()` — the **aggregate-only** sample (CPU times, memory/swap, load, CPU temp) with *no* process table. That third one exists because a process walk is the expensive half: the 🧠 local-model menu polls "how loaded is this machine, and what is left for the next model" every couple of seconds while hovered, and paying a `/proc` read per process (plus the JSON for all of them) for a figure it never shows is a price only the pane's own view justifies. Each platform backend implements it beside its `system_snapshot` from the same primitives, so the two can't disagree; a target with no backend answers `supported: false` rather than zeros. |
| `gpustat.rs` | Whole-**device** GPU memory (the header row, the monitor pane, the model menu's headroom line) — Ollama's `/api/ps` figure is now one line of its breakdown, not the reading. Reports a GPU's **two** pools separately because on an APU only one is real: the dedicated VRAM carve-out (~512 MB — the framebuffer, permanently ~full, so it alone says nothing) and the shared pool mapped out of system RAM (amdgpu's GTT, where a model actually lands); callers sum them, and on a discrete card the shared half is 0 so the sum collapses to plain VRAM. Sources: **DRM sysfs** (`mem_info_*` + `gpu_busy_percent` — no tool, no root) and **`nvidia-smi`** (the only portable NVIDIA read; a process spawn, so its *absence* is remembered rather than re-paid every poll). A card is only reported when it states a `vram_total` — Intel's `i915` exposes none, and a zero is not a measurement. One ~1 s cache serves all three surfaces. Each `GpuSample` also carries the card's **sensors** — temperature, power (draw + cap), core/mem clocks, fan %, PCIe link, driver version — read from the *same* cheap sysfs (a card's `hwmon` subdir + `pp_dpm_*`/`current_link_*`) / `nvidia-smi` pass, so every surface gets them free; each is `None` when the driver won't say (never a fake zero). **Per-process** GPU memory is deliberately separate (`process_snapshot` → `gpu_process_snapshot`, monitor pane only, *not* cached into the shared snapshot): a heavier read (a `/proc` `fdinfo` walk deduped by `drm-client-id` for amdgpu, an `nvidia-smi --query-compute-apps` spawn) the always-visible header must not pay for. A **remote** project samples its host's GPUs too: `sysstat::REMOTE_SNAPSHOT_SCRIPT` ships the host's DRM sysfs files (`AMD\t…` lines) and raw `nvidia-smi` CSV (`NVSMI`/`NVPROC`) over the one SSH round-trip, and `parse_remote_snapshot` runs them through these *same* `parse_drm_card`/`parse_nvidia_smi`/`parse_nvidia_apps` parsers — so a host GPU reads field-for-field like a local one. Remote per-process is NVIDIA-only (the AMD `fdinfo` walk is too heavy to run per remote poll). |

**Commands (`commands/`)** — Tauri command handlers exposed to the frontend.

| File | Purpose |
|------|---------|
| `projects.rs` | Project CRUD, scaffold/import, time-today (god module; #1). Also the **duplicate gate** (#152): `find_project_conflict` is the one answer to "is this already a project", asked by `create_project`, `import_project`, `finish_import` and `extend_project_to_remote` so four call sites cannot drift into four definitions. It compares a `ProjectSite`, not a path string, and the distinction is the whole point — a *local* project is its directory (canonicalized, so a trailing slash or a symlink cannot smuggle a second registration past it), a *remote* one is its SSH target + host path, because its registered `directory` is a per-id state dir that never matches twice however often the same host folder is imported. A remote project's **mirror** counts as an owned tree too. `import_project` runs it **before** the mode dispatch moves anything: the check used to see only the destination, so a `move` re-import under a new name moved the tree out from under the original entry. `copy` is deliberately exempt (new directory, source left registered and intact). `check_project_site` is the same resolver as a read-only query, so the dialog can warn — and offer to open the existing project — before a clone downloads a repo that would be refused. |
| `fs.rs` | File-I/O commands (read/write/mtime, extracted from `projects.rs`; #1 seam). |
| `fs_watch.rs` | Filesystem watch start/stop + change events. |
| `git.rs` | Git status/history/commit/push. Also the **worktree** surface (#23, `docs/worktree_improvement_plan.md`), whose three non-obvious rules are all about the fact that the git verb is the easy part. **Where the operation runs is not where the bytes the user picked live**: for a remote project `project_dir` is the *local mirror*, so resolving remoteness from it alone created host worktrees at mirror-shaped paths and left the mirror's own repo unmanageable — `WorktreeSite` makes the choice explicit, following `git_publish`'s `PublishSite`. **A worktree has exactly one legitimate home**: `git worktree add <path>` creates *and populates* `<path>`, i.e. an unconstrained path argument is a "write repo-controlled content anywhere writable" primitive, including somewhere Eldrun later reads back as intent (#151) — so `resolve_worktree_path` confines every one to `<root>/.eldrun/worktrees/`, which also makes it invisible to both byte-sync walkers and *visible* inside the container (the linked `.git` file's `gitdir:` pointer resolves, because the project dir is mounted at its identical absolute path). **`worktree add` checks out, and a checkout runs hooks**: `NO_HOOKS_CONFIG` (`-c core.hooksPath=`) is pinned on these verbs and on `git_checkout`, deliberately *not* in `HARDENED_CONFIG`, which `git_commit` also goes through and where the user's own hooks are the point. `force` on remove is a **count**, not a flag — git answers a locked worktree with "use 'remove -f -f'" and exits 128 for a single `--force`. |
| `git_publish.rs` | Publish a project's repo to GitHub (`gh`) or GitLab (`glab`). Owns the shared `Provider` (which CLI, which token/host env). Also owns **which side runs the CLI** (`PublishSite`), which is the one non-obvious thing here: *where the bytes are is not where the hosting account is*. `gh auth login` and the Settings → Git Hosting tokens are secrets of the local machine, while a work remote is typically a cluster login node with no provider CLI, no GitHub credentials and often no outbound https — so a remote project publishes **from its lockstep mirror by default** (`publish_from = "local"`, the dialog's "Publish from" selector), and the ssh path is the explicit opt-in for a host with its own login. The local default's one hazard is a stale mirror, so `describe_mirror_guard` (pure, tested) refuses unless lockstep is enabled *and* green — otherwise a publish would create the repo from the wrong history. Every follow-up (visibility, unpublish, and `commands::git::git_push` via `mirror_origin_repo`) routes by `origin_site`: wherever `origin` actually got wired, so the create and the pushes never end up on opposite sides. `run_remote_provider_command` additionally translates OpenSSH's own failures (`ssh_transport_error`) — `ssh_base_args` reuses but never creates a master, so a disconnected project fails at ssh auth, and "Permission denied (publickey,password)" reads like a GitHub rejection if passed through raw. |
| `git_fork.rs` | The import dialog's **fork** source: fork a hosted repo into the user's own account, then clone *that*. A fork is a server-side operation, so it goes through the provider CLI's raw `api` subcommand (`gh api -X POST repos/<owner>/<repo>/forks`, `glab api -X POST projects/<id>/fork`) rather than `repo fork --clone` — the response JSON *names* the fork, and neither CLI's clone can be pointed at a destination directory or have its namespace guessed (a fork can land elsewhere, or already exist: GitHub returns the existing one, GitLab refuses with "already been taken", which is looked up instead of reported). The clone itself is `git::git_clone_blocking`, so the URL whitelist, token credential helper and partial-directory cleanup are the ordinary clone's; it is retried only on the "not there yet" failure, since forking is asynchronous on both services. `git remote add upstream <original>` is best-effort — the tree is on disk by then. `fork_cli_available` backs the dialog's install banner. |
| `terminal.rs` | Terminal/PTY command surface (delegates to `terminal/mod.rs`). Also the **local** tmux-session commands (TODO #85): `local_tmux_{list,kill,rename}`, and the `pty_spawn` local-tmux wrap (`services::tmux_local`). |
| `apps.rs` | App launching, `run_script_detached`, `open_file`, external window tracking. |
| `default_apps.rs` | Per-file-type default-app mapping. |
| `downloads.rs` | Per-project download routing. |
| `ssh.rs` | SSH commands for remote projects (`ssh_connect`, `ssh_default_dir`, `ssh_list_dir`, `ssh_tooling_status`). Also the **active-disconnect** pair (explicit-click only, never on relaunch): `remote_kill_all_jobs` (`tmux kill-server` on a host — ends *every* running session/job, best-effort, rides a live master or authenticates ad-hoc like `global_machine_monitor_snapshot`) and `ssh_close_master` (`ssh -O exit` on the shared `cm-%C` socket, for a project-free global machine that pools nothing; a project host tears its pool down via `remote_disconnect` instead). |
| `remote.rs` | Pooled SSH/SFTP connection lifecycle (`remote_connect`/`remote_disconnect`) for the active remote project. Also `remote_upload_file` (HPC wizard "Load data" step, `docs/quirky-knitting-umbrella`): streams a local file to `<remote_path>/<dest_rel>` over the pooled SFTP (`upload_file_streaming_on`), primary host, dest_rel sanitized to stay inside the root. Also the tmux-session commands (TODO #85): `remote_tmux_list` (Sessions view, `tmux ls` → `Vec<TmuxSession>`; called per-host so the view aggregates every connected worker), `remote_tmux_kill` (explicit-close / per-row kill), and `remote_tmux_rename` (per-row rename), all over the pooled ControlMaster. |
| `openvpn.rs` | OpenVPN tunnel connect/store-config commands. |
| `ollama.rs` | Ollama model list/pull/delete + local autocomplete. |
| `tex.rs` | TeX compile + SyncTeX (shell-escape defense). `compile_tex` is **async** (`spawn_blocking`): a sync command runs on the main thread, so every TeX-figure add and every Recompile used to freeze the whole webview for up to the 600 s run timeout. Also home to two commands the deck presenter needs. **`synctex_page_lines`** reads the `.synctex.gz` a compile already emits (`-synctex=1` is passed unconditionally) and reports the source lines behind each PDF page — the *producer* half of a deck slide's line anchor, which `sidecar.ts` documented and consumed but nothing ever wrote, so the mechanism did not exist at runtime. It parses the file rather than shelling out to `synctex edit` per page (a 200-page plate would be 200 process spawns for one reconcile), and harvests only the **main input's** tag, because line numbers from two files are not comparable and mixing them would be an anchor that silently means nothing. **`list_fonts`** walks the platform font directories for formats fontkit can embed, returning **paths** — the frontend measures and embeds by path, since two files can claim one family name and the export would otherwise be a coin flip. |
| `boxes.rs` | Project-box CRUD. |
| `browser.rs` | **In-app browser** (TODO J #61, `docs/browser_plan_{a,b,c}.md`). Two surfaces, deliberately *neither* an embedded pane: an in-pane **reader** tab whose page is fetched and sanitized in Rust (`browser_reader_fetch` → the mail client's own `ammonia` pipeline → inert HTML in a `sandbox=""` srcdoc frame, so **no JavaScript ever runs**), and a separate hardened **live-page window** (`browser_open_live`). An embedded child webview was ruled out because it does not work: `tauri-runtime-wry` packs one into the window's `GtkBox`, where `set_bounds` is a no-op, so N webviews stack vertically. The command surface is path-free, enforced the same way `mail.rs` enforces it (`no_command_takes_a_path` reads this file's own source) — with **one** documented exception, `url`, safe only because every one goes through `web_safety::navigation_decision` first and that gate hard-blocks `file:`/`tauri:`/`asset:`/`ipc:`/`javascript:`/`data:`/`blob:`. The live window is `incognito(true)` (ephemeral profile; nothing on disk, so quitting *is* the delete), `browser_extensions_enabled(false)`, `on_new_window` → `Deny` (a popup would be a chromeless window with no address bar), and `on_download` installed — wry's DEFAULT download handler allows *every* download to a path the page chose. Downloads land in `<state_dir>/browser/quarantine/` (0700, file 0600, exec bits stripped, never a project tree) and reach disk only via the native save dialog raised from Rust; `browser_download_decide` returns a **display name, never a path**. **Two gates, deliberately separate.** `LIVE_SUPPORTED` is false on Windows (WebView2's default permission state draws *Edge's own* prompt, whose Allow grants a browsed page the camera) — same posture as `services::sandbox` #86; `READER_SUPPORTED` is true everywhere, because that refusal is entirely about a *webview's* permission model and reader mode has none. They were one constant, which is how the Windows refusal silently spread to a surface its reason does not apply to. On top of the platform gate the live window needs `Settings::browser_live_pages`, **default off and off in debug too** (not an `experimental()` flag): two of its holes cannot be closed from app code, so it is opt-in rather than a line item inside `web_browser`. `browser_capabilities` folds both into one bool — the frontend's only question is whether to offer the control — and `browser_open_live` re-reads the setting rather than trusting that report. A tripwire suite scans the whole backend for the defences that would be silent if deleted: no certificate escape hatch, no permission/clipboard handler, no `register_uri_scheme_protocol` (every registered scheme is a *local* origin), no `ipc::Channel` (readable by any webview via the ACL-exempt `plugin:__TAURI_CHANNEL__|fetch`), no second keychain path, no foreign-browser-profile access. |
| `calendar.rs` | Calendar/event/task CRUD over `calendar.json` + guarded ICS file read/write. Also the **to-do board's** two commands, and they are the only two the board needs — everything else (load, create/edit/delete a card, filters, convert-a-mail, both rails) reuses the existing task CRUD and `mail_priority_*`. `todo_move_tasks` applies a whole drag in ONE write: the frontend sends an **index**, never a rank, so the rank algebra (bisect, the too-close-to-split guard, the whole-column reindex to clean `RANK_GAP` multiples) lives in one tested place and a replayed placement is a no-op; it takes ids + target rather than a whole `CalendarData`, so a concurrent title edit in another window survives the same read-modify-write, and it **never refuses** a move for a WIP cap (a drag that reports success and snaps back is indistinguishable from a broken one). `todo_columns_set` is wholesale because a reorder is the common edit and a delete must refile its cards in the same write. Both call `ensure_board` — the board's columns are seeded by its first **write**, never by a read, which is what keeps a calendar-only user's file free of board state. Two long-standing bugs the board made load-bearing were fixed here: `create_task`/`update_task` returned the *pre-normalize* clone (so a new card came back with no column and did not render, and ticking in the Tasks view returned the stale column), and `write_data` truncated in place instead of using `write_json_atomic` — this file is now written on every drag, from a second window too. |
| `mail.rs` (priority marks) | `mail_priority_{set,page,counts}` — the **Important / Urgent** lists, and the only mail commands that touch **no network at all**. That is forced by what the feature is: the lists span *every account*, and no IMAP folder can hold two accounts' mail, so a cross-account list can only be a local column (`schema::mail::MailPriority`). A real server-side move would need one folder per account, a round trip per mark, and would mint new UIDs — invalidating every cached body, attachment row and store key for the message, with a half-applied state whenever one account's server refused. The mark is deliberately not `\Flagged` either: the star already means something and round-trips, and overloading it would make "starred" and "important" one bit under two names. The honest cost, stated in the schema and in the UI: a mark is *this machine's* and no other mail client sees it. `mail_priority_page` is the twin of `mail_headers` (same paging, same bound `LIKE`, same closed-set `MailSort`), so the frontend keeps one list. |
| `printing.rs` | **The native print manager** (the tab that replaced the `print_manager` global-app slot): one `print_system_snapshot` read plus cancel / cancel-all / set-default / pause-resume / test-page. Two backends behind one shape — **CUPS** (`lpstat`/`lpq` to read, `cancel`/`lpoptions`/`cupsenable`/`lp` to act; Linux + macOS) and **Windows** (one PowerShell script per read, returning JSON) — mapped onto the same small closed set of state words, so an unrecognized value degrades to `unknown` and never to something healthy-looking. Three rules carry it. Every CUPS read runs under **`LC_ALL=C`**: those tools translate their output ("is idle" → "ist im Leerlauf") and every parser here would go blind under a German locale. Every probe is **time-capped** (`run_capped`, 8 s, both pipes drained on threads) and runs in `spawn_blocking`, because `lpstat` talks to a CUPS server that may be a machine behind a dead VPN and a synchronous command would wait with it — with the window. And **nothing is spawned through a shell**: names reach `Command` as argv, so a printer called `; rm -rf ~` is a printer with a silly name; the Windows path, where a script genuinely *is* a string, is the exception that proves it (`check_printer_name` refuses the interesting characters, then `ps_quote` doubles what is left). Default is set with `lpoptions -d` (the **user's** default), never `lpadmin -d`, so no action here raises a password prompt. A missing print system is a *state* (`supported: false` + a sentence), not an error. `print_test_page` is the closest thing to a write, and it takes **no path**: the backend writes the page itself, so no caller can turn the print manager into a print-this-file command. Pure parsers (`parse_lpstat_{printers,default,accepting,jobs}`, `parse_lpq_titles`, `parse_windows_snapshot`) are unit-tested — including `ConvertTo-Json` collapsing a one-element array into a bare object, the Windows shape that cannot be checked on Linux any other way. |
| `subwindow.rs` | Detached/popped-out subwindow lifecycle (#42). |
| `presenter.rs` | The deck presenter's **audience window** (M#90): open it on the second monitor, close it, and keep the screen awake. Deliberately not a detached subwindow — it must never be *parked* by `project_runtime::switch`, which mid-talk would blank the projector. Fullscreen is applied **inside** the deferred first-paint kick, not before it: WebKitGTK shows an unpainted black GL surface until a genuine OS-level resize, and the ±1 nudge that forces one was guarded on `!is_fullscreen()` — so whenever a second monitor *was* found the workaround skipped precisely the case it exists for. `presenter_{inhibit,release}_sleep` hold a `systemd-inhibit` child for the length of a talk (Linux; a no-op elsewhere): the inhibition lasts exactly as long as the child, so killing it is the release and a crashed Eldrun releases it too. |
| `timer.rs` | Time-tracking commands. |
| `usage_stats.rs` | Usage recap: batched counter writes (`usage_bump`), rollup reads, watcher attach, and git commits/lines derived on demand from `git log`. |
| `workspace.rs` | KDE/X11 workspace switch commands. |
| `settings.rs` | Settings read/update. |
| `project_runtime.rs` | Project-switch runtime command wrapper (off-UI-thread). |
| `slurm.rs` | **SLURM run/watch core for HPC projects** (`docs/quirky-knitting-umbrella` plan): `slurm_available`/`slurm_submit`/`slurm_queue`/`slurm_job_out`/`slurm_cancel`. Mirrors `python.rs`'s dispatch — resolves `project_dir` (+ optional `host_id`, primary default) to a remote target and runs a POSIX-`sh` script over the pooled ControlMaster (`run_remote_script`), or a local shell for a login node that itself has SLURM. **Security**: the script is embedded verbatim, so every path is `shell_quote`d (the shared `ssh_exec` helper) and a job id is validated numeric before it touches `scontrol`/`scancel`. `slurm_submit` chains `sbatch --parsable` → `scontrol show job` in ONE round trip (the id comes from sbatch, so nothing user-controlled is interpolated) and returns the SLURM-resolved absolute out/err/work paths. Pure parsers (`parse_submit_jobid`, `parse_scontrol_paths`, `parse_squeue`, `split_script_rel` — which preserves absolute paths so the frontend can pass a file's absolute path and skip any remote-vs-local rel computation) are unit-tested. |
| `hpc_ws.rs` | **HPC workspaces** (`docs/quirky-knitting-umbrella` Phase C): `hpc_ws_available`/`hpc_ws_list`/`hpc_ws_allocate`/`hpc_ws_extend`/`hpc_ws_release`/`hpc_ws_link` over the `hpc-workspace` tooling (`ws_allocate`/`ws_list`/`ws_find`/`ws_extend`/`ws_release`). On a cluster `$HOME` is a small quota'd code filesystem and the bulk data belongs in a **time-limited workspace** on the parallel filesystem — so this is the step that must precede any upload/sync, and its whole integration is that the allocated path becomes the project's **remote root** (every existing transport then lands there unchanged). **Nothing is site-specific**: the host is *asked* what it offers (`ws_list -l`) instead of presets being hardcoded. Reuses `commands::slurm`'s dispatch verbatim (`run_slurm_script`, now `pub(crate)`) for a project target, and — because a workspace is normally allocated **before the project exists** — adds a bare-host target authenticated ad-hoc via `run_ssh_auth`, exactly as `global_machine_usage_check` does. Each list/allocate is ONE round trip that appends a `ws_find` confirmation, because the *path* is the field everything downstream depends on and `ws_list`'s layout differs between versions. **Security**: every interpolated value is validated (id/filesystem/link-name charset, day counts bounded, mail free of metacharacters) *and* `shell_quote`d. Pure parsers (`parse_ws_locations`, `parse_ws_list`, `parse_ws_allocate`) are unit-tested. `hpc_ws_link` symlinks a workspace into a project that stayed in `$HOME`; the link is for the **host's** tools only — byte-sync never follows a symlink (`remote_sync::walk_host_files`, G3). Also the two commands that make the layout survivable (`docs/hpc_workspace_plan.md` Phases 1–2): **`hpc_ws_anchor`** creates the small per-project folder in the cluster `$HOME` (`logs/`, a `workspace` symlink, and an **append-only** `workspaces.txt` record) — append-only because a project passes through several workspaces a year and the *previous* names are what `ws_restore` needs; its `$HOME`-relative path is validated segment-by-segment (with `.`/`..` rejected explicitly, since `validate_token` allows `.` inside a name) so it cannot escape home. **`hpc_ws_move_root`** re-points a primary's `remote_path` — the escape hatch an expiry makes inevitable, and which nothing else could do (a primary's path was fixed at creation) — rewriting `project.json` + the mirrored `extra["remote"]`, resetting lockstep state to a fresh `enabled` and clearing the byte-sync manifest's per-file **bases** while keeping every marker (stale bases would claim the new, empty root holds files, which the safe-direction policy reads as "the host deleted them"). `set_project_hpc` persists the record (both files, like `set_project_run_host`); `hpc_ws_pull_logs` copies the anchor's logs into the mirror. **`hpc_scratch_candidates`** is what keeps the feature true of *any* cluster rather than the `hpc-workspace` ones: at a site with no `ws_allocate` it asks whether the site's own profile exports `$SCRATCH`/`$WORK`/… (plus two conventional paths), reporting each existing directory with writability + `df` free space, so the Workspace step can still offer a big filesystem instead of dropping the project into `$HOME`. The probed variable *names* are the one site-shaped list in the module — names to ask about, nothing assumed about what they mean. |
| `python.rs` | Which Python the viewer's Run/Debug run (#87), and the **single** source of that precedence — the frontend asks, it never re-derives. A project's pinned `python_interpreter` always wins (and costs no probing); otherwise auto-detect ranks in-tree venv → poetry → active `VIRTUAL_ENV`/`CONDA_PREFIX` → pyenv → system. A **named conda env is offered but never auto-picked**: choosing one of N unrelated envs on the user's behalf is a guess, and a wrong one here is indistinguishable from a bug. Remote projects probe the **host** (one constant `sh` script over `run_remote_script`) — the interpreter that matters is the one on the machine the run tab runs on. |
| `pdf_clip.rs` | In-memory transfer slot for dragged/copied PDF *pages*. Two Eldrun windows are separate WebViews with separate JS heaps, so the bytes must cross the process boundary; events carry only the token. |
| `crash.rs` | Receives frontend renderer crash reports. |
| `debug.rs` | Debug-mode helpers. |

**Services (`services/`)** — `AppHandle`-free, unit-testable.

| `big_folders.rs` | The giant-folder census behind the setup prompt (`BigFolderExcludeDialog`): *which folders are too big to sync*, asked for the whole project on **both** sides at the one moment the answer is cheap — before the first pass moved anything. The two sides are measured differently (a local walk; one `du -ak -x` over the pooled ControlMaster via `ssh_exec::remote_du_raw`) and reduced to the SAME shape — a flat `(rel, bytes)` file list — so `tally_dirs` + `pick` are one pure, side-agnostic, unit-tested heuristic rather than two that can disagree. `pick` reports the **shallowest** folder over either threshold (2k files OR 512 MB — count is what makes a pass take minutes, bytes is what fills the disk), except that a folder whose weight is concentrated in one child is skipped in favour of that child, so the prompt says `data/raw` rather than `data`. | `browser_engine.rs` | The browser's engine-side work: the reader fetch (rustls, OS trust store, no cookies, no `Referer`, fixed generic UA, 15 s / 5 MB / 3-hop caps, charset from the header then `<meta>` then UTF-8 — never the renderer's sniffing), the live-window registry, and download quarantine + sniffing (`infer` + `mime_guess`, executable magic, the zip-container aliases so a `.docx` is not a "mismatch"). Two rules carry most of the weight. **Hop 0 vs. later hops**: the URL the *user* asked for may be a loopback/private address (a dev server is a real thing), but a hop the *server* chose may not — that is the whole SSRF defence for a backend fetch. It takes **two** halves to mean anything, and shipping only the first is the mistake the audit caught: `reader_hop_allowed` judges the address *literal* (all a pure function can do), and `resolve_hop` resolves each hop and refuses one whose every address is not globally routable — without it, `169-254-169-254.<any public wildcard resolver>` is an ordinary domain name and the metadata endpoint is one redirect away. The connection is then **pinned** to the addresses that were checked (`resolve_to_addrs`), because a check-then-connect gate that lets the resolver answer twice is decoration. Gaps disclosed in the module header rather than glossed, all of them the **live window's**: there is **no sub-resource request filter on any platform** (`on_navigation` sees navigations, not `fetch`, and `on_web_resource_request` only ever fires for Tauri's own `tauri://` protocol); a live page can reach a loopback service **by name** for the same DNS reason, unfixable here because WebKit resolves after the synchronous callback; `ws://` reaches one regardless of the scheme allowlist (a WebSocket is not a navigation, and WebSocket has no CORS); and **autoplay cannot be disabled** (wry defaults it on and Tauri never sets it). Those are why the live window is opt-in. |

| `mail_authres.rs` | **`Authentication-Results` (RFC 8601)** — SPF/DKIM/DMARC as the *receiving server* reported them, which is most of what PGP would otherwise be needed for at a fraction of the surface: the MTA already did the work (SPF is about a connecting IP that is long gone by the time IMAP hands us bytes, and DKIM is a crypto stack) and wrote the answer into a header. The whole module is about which header may be believed. **Only the topmost instance is read** (headers are prepended, so the top one is the last hop's — yours) **and only if its `authserv-id` equals the account's configured one**, because position identifies a slot, not an author: without the id check a message your server never stamped presents the sender's own forgery in the top position. With no id configured the state is `Unconfigured` and **no verdict is shown at all** — a tick nobody checked is worse than no tick, since it teaches the user to trust something an attacker can draw. `apply_trust` is deliberately separate from parsing and runs on **every read**, so setting or clearing the id re-judges already-synced mail with no re-sync, and it *clears* `methods` outside `Verified` so stale data cannot leak through a future UI bug. Comments are stripped before anything is split — a real header carries `dkim=pass (1024-bit key; unprotected) header.d=…`, whose parenthesis holds both a `;` and an `=`, so not stripping first invents a clause boundary out of prose. Every clause keeps its `identifier` and an `aligned` flag against the visible `From`: `dkim=pass header.d=evil.example` on a mail claiming to be a bank is a *genuine* pass by the wrong signer, and that is the single most common misreading of these headers. The limit it cannot fix, stated in the module header rather than glossed: if your provider adds no header and an attacker forges one bearing its id, this believes it — RFC 8601 §5 puts the duty to strip forged instances on the MTA. |
| `mail_crypt.rs` | **The local mail store, encrypted at rest** (`docs/context/mail_encryption.md`) — the primitive and the key, and nothing else. One `ELMC` envelope shape (XChaCha20-Poly1305; the 192-bit nonce is drawn at random, so there is no counter to survive a crash *and* a restore-from-backup, which is how AES-GCM nonce reuse actually happens), HKDF subkeys off one master (`k_field`/`k_blob`/`k_addr`/`k_name`/`k_wrap` — compromise of one does not hand over the others), and a key file wrapping that master under either an OS-keychain KEK or an Argon2id passphrase (parameters recorded *in* the file, so they can be raised later without stranding a store). The load-bearing part is the **AAD**: every ciphertext is bound to `account‖table‖column‖row`, so an attacker with disk *write* access cannot relocate one message's sealed body onto another's row and have it render as that message — the class of attack at-rest encryption is famous for leaving open. `Unlock::Unavailable` is a **state, not an error**: a locked Secret Service collection reads identically to "nothing saved" and can block forever (the failure that once parked every connection lamp on amber), so the caller degrades to a memory-only store rather than making the mailbox unreadable. |
| `mail_crypto.rs` | The **format-agnostic seam** for end-to-end mail — what the *sender* did before the message left their machine, as opposed to `mail_crypt`'s at-rest job or `mail_authres`'s "what did my server conclude about the delivering hop". Detection is about **structure, not validity** (`CryptoKind` says what a message claims; whether it holds is a separate question), which is what let detection ship before verification without a half-built verifier being able to report a pass. Inline armor matches only at a line start, so a mailing-list thread *about* PGP does not grow a padlock, and a MIME wrapper outranks armor inside it (that armor is the ciphertext, not the message). **S/MIME is detected and not handled** — a recognized-but-unsupported format renders a banner; an unrecognized one renders its ASN.1 blob as though it were the mail. `info_for` is the single place the chrome rule lives: positive chrome needs a good signature **and** a key the user verified out of band **and** an identity matching the visible `From`; `Invalid` and `NoKey` are separate states, because "this is forged" and "I cannot tell" are different sentences. Every signed message carries a `headers-not-signed` note, because From/Subject/Date sit outside the signature in both formats and that is the thing users most reliably assume a tick covers. |
| `mail_pgp.rs` | The **OpenPGP keyring and the four operations** (rPGP; sequoia is LGPL and Nettle-by-default, which the no-C-toolchain invariant rules out). Sealed under `k_wrap` — deliberately not `k_field`, so the mail index and the private keys are not one compromise — and `open` takes `MailKeys`, so there is no unencrypted path by construction. **Key generation offers no algorithm choice**: `pgp` depends on `rsa` unconditionally and RUSTSEC-2023-0071 is unpatched, but the oracle is in RSA *decryption* and nobody can encrypt to a key we do not have, so Curve25519-only means that code is compiled in and never run for our mail (RSA stays importable — a correspondent's key is only ever used to verify). An imported key is `Known`, **never** `Verified`: OpenPGP has no CA, so only an explicit fingerprint comparison promotes it. `candidates_for` returns every key that *could* have signed, matching the primary **and every subkey** (signing is done by a subkey on every ordinary key, so matching the primary alone reports "no key" for keys we hold), and lets the cryptography pick — a 64-bit key id is short enough to collide on purpose. `signed_part_bytes` is the most dangerous function here and is commented as such: its failure is silent *and positive*, so it slices the **raw** message (RFC 3156 signs the part including its MIME headers, in transfer-encoded form) and drops the CRLF that introduces the closing boundary. `seal_outgoing` signs **inside** the encryption (the other order lets anyone strip and re-sign the ciphertext as their own) and has no path that returns plaintext on failure. |
| `web_safety.rs` | Shared web-safety primitives, extracted from `mail_sanitize` so the mail client and the browser cannot drift apart: `sanitize_attachment_name` (a message and a page pick filenames the same way), the host/scheme primitives (`scheme_of`/`host_of`/`idna_display`/`registrable`/`has_userinfo`), and the **navigation gate**. `mail_sanitize` re-exports the moved items, so every mail call site and its whole test table are untouched. Three outcomes (Allow / Confirm / Block), an allowlist of `http`/`https`/`about:blank`/`about:srcdoc` plus an explicit deny list, and the **app-origin rule in BOTH build profiles**: Tauri's `is_local_url` calls the dev server (`http://localhost:1420`) and every `*.localhost` origin *local*, so a browser that reached one would clear the origin half of the ACL gate. `registrable()` stays the two-label approximation on purpose — moving it to a real PSL would change mail's cached mismatch decisions and needs its own `SANITIZER_VERSION` bump (so the address bar emphasizes the whole host, a documented+tested v1 limitation rather than a wrong guess). `REASON_TOKENS` is the **canonical list of every reason token a user can be shown**: the gate deliberately speaks in machine tokens so the wording can live in the frontend's i18n ×5, which is only safe because a Rust test proves the list covers every `BlockReason`/`ConfirmReason` variant and `src/__tests__/BrowserTripwire.test.ts` reads the list out of this file and fails if any entry has no phrase. |
